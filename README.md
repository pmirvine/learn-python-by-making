# Learn Python by Making

A project-based Python tutorial for people who can already program a little and want to know Python properly. Twenty-eight projects, from a guessing game to a home-made computer that boots to a BASIC prompt, with a BBC Micro accent throughout: every project makes something you can see, hear or play with.

Along the way it teaches the working habits of professional Python: uv, Git, VS Code, pytest, ruff, type hints, packaging and CI, each introduced when a project needs it.

> **Status: pilot.** Part 0, Project 1 (Hi-Lo) and Project 8 (Mode 2 Sketchpad) are written. [`PLAN.md`](PLAN.md) has the full curriculum, and the [roadmap](docs/roadmap.md) shows progress.

## Reading it

The tutorial is a website, built from the Markdown in `docs/`. To read it locally you need [uv](https://docs.astral.sh/uv/):

```console
$ uv run zensical serve
```

Then open <http://localhost:8000>. The chapters are readable on GitHub as well, though the callout boxes and tabs only look right on the site.

## What's in the repository

```text
docs/        the chapters, in Markdown
projects/    the code for every project, laid out as a reader's own project would be
  NN-name/
    stages/      the code as it stands at the end of each stage of the chapter
    bughunt/     the deliberately broken file for the chapter's bug hunt
    solutions/   solutions to the Tweak and Extend challenges
scripts/     tools for checking and building the tutorial
tests/       tests for the projects that come before the tutorial teaches testing
PLAN.md      the curriculum, and the decisions behind it
STYLE.md     how the tutorial is written
```

## Checking it

Everything in the tutorial is tested: the projects, every stage snapshot, and the chapters themselves.

```console
$ uv run scripts/check_all.py
```

For each project, that checks its lockfile, lints and formats it with ruff, and runs its tests, all inside the project's own environment, just as a reader would. Then `scripts/check_docs.py` checks the chapters: every code listing must match the file it claims to show, every REPL session is run as a doctest, and every "Predict" snippet is run to make sure the published answer is right. Finally it builds the site.

Pygame projects are tested without a display, using SDL's dummy video driver. Screenshots are generated by script (`scripts/screenshots_p08.py`) and never captured by hand.

## Corrections welcome

The macOS instructions have been tested first-hand. The Windows and Linux setup instructions come from each tool's documentation and are marked as unverified until somebody confirms them. If you follow them and something doesn't match, please open an issue.
